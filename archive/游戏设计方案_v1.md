## 一、目标玩家与三条硬约束

> ## ⚠ 第一条硬约束已废止（2026-10-08）
>
> **原文**：「任何一次失败，都不能让孩子觉得『我不行』。」
>
> **废止理由**：这条约束与题材的核心机制冲突。重生题材**需要死亡发生**——
> 不死的游戏里，「重生保留记忆」是句空话。模拟数据也证明：把死亡率压到
> 这条约束要求的水平（HP 20，死亡率 0.5%），六座副本全程只有 **3%** 的玩家
> 会经历死亡，等于**把最核心的机制做成死代码**。
>
> **取代它的是「死亡必须教会东西」**（见 v3 第一节）：死亡可以发生、可以让孩子
> 难过，但**每一次死亡都必须带来确定的可复用情报**，让孩子第二天会去想
> 「上次那里有个洞，我这次带火把」。
>
> 下面的原条文保留作历史记录，**不再作为设计判据**。

**8-10 岁 = 小学 2-4 年级。** 这个年龄的真实边界：

- **阅读**：能独立读短句，长段落会累。一屏 100 字就是「又要读一大堆」。
- **心算**：2 年级 100 以内加减 + 表内乘法；3 年级万以内加减 + 多位数乘一位数 + 除法；4 年级三位数乘两位数 + 四则混合。
- **挫败容忍**：低。连续失败 2-3 次就会放下不玩了。
- **成就感来源**：**「我变强了」+「我知道得更多了」**，而不是「我通关了」。

由此得出三条硬约束，整个设计都要服从它们：

1. ~~**任何一次失败，都不能让孩子觉得「我不行」**——只能让他觉得「我还不知道」。~~ ~~这条直接决定了数学题和死亡机制的设计。~~ **← 已于 2026-10-08 废止，见上方说明。取代它的是「死亡必须教会东西」。**
2. **不能有看起来像陷阱的选项。** 孩子会自责选错了，而不是觉得游戏设计有问题。
   > **2026-10-08 精化**：D&D 式扣血引入了「花 HP 换宝物」「选错扣血」的选项，
   > 这条约束**保留但需要明确边界**：**扣血的选项必须在选之前就显示代价**
   > （如「打开铁箱（-3 血）」），而不是选完才发现被扣。
   > **可以代价高昂，不可以是暗雷。** 见 v3 第一节。
3. **文字是装饰，不是关卡。** 读懂剧情应该让游戏更有趣，而不是成为通关的必要条件。

## 二、核心循环

```
小镇公会 ──▶ 看悬赏 ──▶ 判断「我打不打得过」──▶ 出发
   ▲                                              │
   │                                              ▼
   └── 交任务拿报酬 ◀── 战斗/解谜 ◀── 途中遭遇（数学题、抉择）
                              │
                              ▼
                        死亡 ──▶ 重生（数值清零，记忆保留）
                              │
                              └──▶ 回到公会（但你知道得更多了）
```

**「判断打不打得过」是整个游戏最核心的思考动作。** 其他所有系统都是为它提供信息、或为判断失误兜底。

---

## 三、种族系统（5 个，不能有强弱）

选种族是玩家做的第一个决定，也是最有感情投入的决定。**绝对不能有「选错了」的感觉。**

| 种族 | 能力 | 具体机制 |
|---|---|---|
| **兔** | 疾行 | 遭遇战多一个「逃跑」选项，且逃跑必定成功 |
| **熊** | 蛮力 | 战斗中答错数学题时，受的伤减半（耐揍） |
| **狐狸** | 机敏 | 每场战斗可用 1 次「排除一个错误答案」 |
| **猫头鹰** | 洞察 | 接任务前能看到完整情报（其他种族只看到危险等级） |
| **鼠** | 灵巧 | 能钻进窄小通道，开启其他种族到不了的路线 |

设计原则：
- **每个种族都有「只有它能做的事」**，都能通关。差异是玩法，不是强弱。
- 能力要和数学题机制咬合。比如熊的抗错、狐狸的提示——**这三个种族其实是在用不同方式降低数学挫败感**，这是刻意的。
- 不设「种族克制」。对 8 岁孩子，「我选的族更强」比「策略平衡」重要。

## 四、任务与难度判断（游戏的心智核心）

### 任务卡长这样

```
┌─────────────────────────────┐
│ 悬赏：谷仓里的黑影           │
│ 危险：★★☆☆☆                │
│ 报酬：15 枚银币              │
│                             │
│ 委托人说：「夜里听见东西在   │
│ 啃木头。很大。」             │
└─────────────────────────────┘
```

### 玩家靠三层信息做判断

| 层次 | 内容 | 谁能看到 |
|---|---|---|
| 第一层 | 危险星级 + 报酬 | 所有人 |
| 第二层 | 委托人描述里的线索（「啃木头」→ 草食、怕火） | 所有人，但要会读 |
| 第三层 | **「我在这里死过」** | 死过一次之后 |

**第三层就是重生机制和核心玩法的交汇点。** 死亡在这里不是惩罚，是**花一条命买情报**。

### 难度判定简化到什么程度

对 8-10 岁，规则必须是**一眼能懂的一维比较**：

> 你的战斗力 **5** vs 任务危险度 **6** → 会打得很吃力

不做攻防属性、不做克制关系。一个数字比大小，就够撑起整个「判断」玩法了。

## 五、数学题系统

### 5.1 出题时机：三个叙事上自然需要「算点什么」的地方

1. **战斗**：念咒语、放技能 → 算对了造成伤害
2. **解谜**：开石门、破暗号 → 算对了推进剧情
3. **交易**（可选）：买东西算找零 → 算对了省钱

### 5.2 最重要的一条：答错 ≠ 死

| 场景 | 答错后果 |
|---|---|
| 战斗中 | 敌人反击，**扣血但战斗继续**，可以再答 |
| 解谜中 | 暂时打不开，**可以换条路，或先去找线索** |
| 交易中 | 多花钱，不影响生死 |

**绝对不做的事：答错一次就直接死亡。**

理由：8-10 岁的孩子会把「数学题答错」和「我数学不好」直接连起来。如果答错就死，这个游戏会变成**数学焦虑训练器**——这是儿童教育游戏最常见、也最致命的失败。要让孩子觉得「算错没关系，再来一次」。

### 5.3 难度自适应：把孩子稳在「最近发展区」

题库按学段分三档，**档位由孩子自己的表现决定**，不需要家长设置：

| 档位 | 题目类型 | 升档条件 |
|---|---|---|
| 低（2 年级） | 100 以内加减、表内乘法 | 起始 |
| 中（3 年级） | 万以内加减、多位数 × 一位数、除数是一位数的除法 | 连续答对 3 题 |
| 高（4 年级） | 三位数 × 两位数、除数是两位数的除法、四则混合 | 连续答对 5 题 |

答错 2 次降一档。**目标答对率 60-80%** —— 太简单会无聊，太难会放弃，这个区间最理想。

### 5.4 呈现方式：不能像作业

包在叙事里，而且要短：

> 石门上浮出符文，数字在发光：
>
> **47 + 38 = ?**
>
> 算对了，门就会开。

- **4 选 1，不做数字键盘输入**（低龄输入太慢，挫败感强）
- 干扰项要「合理」：来自典型错误（进位忘了、数位对错），不能乱写
- 每题只占一屏的三分之一，永远不遮住剧情

## 六、死亡与重生（这个题材的灵魂）

### 6.1 死亡时发生什么

| 清空 | 保留 |
|---|---|
| 战斗力、装备、银币 → 回到初始 | **记忆**（唯一的、也是最强的进度） |

### 6.2 记忆怎么变成真实机制

重生后，这四件事会不一样：

1. **死过的任务标出来**：「我在这里死过 · 被大老鼠咬的」
2. **见过的敌人**：战斗界面显示弱点提示
3. **走过的路**：不再需要重新探索，直接跳过
4. **答错过的数学题**：重生后会再出现一次 —— **这是刻意的教学复习**

第 4 条是关键。**它让「重来一次」有了教育意义**，而不只是游戏机制。

### 6.3 为什么这个题材天生适合重生

普通游戏里死亡 = 惩罚。这个游戏里死亡 = **获取信息**。

孩子死一次，不是「我失败了」，而是 **「我学到了：那个洞里有大东西，下次要带火把」**。

### 6.4 主界面显示「第 N 次人生」

把轮回数当**徽章**展示，不是伤疤。孩子会主动跟人说「我已经活到第 7 次了」。

## 七、叙事结构

采用 D&D 式展开，但大幅简化：

- **一个中心小镇**（冒险公会所在地）
- **6 个悬赏任务**，每个 10-15 分钟
- **一条隐藏主线**：小镇为什么需要这么多佣兵？

任务之间**互相独立、可任意顺序接取**。对儿童来说，「我自己选」比「按顺序来」重要得多。

### 现有样例内容怎么处理

现在 `data/scenes.js` 里的「雨夜小屋 / 灯塔」是成人向的占位内容（雨夜、油灯、无人村），**和儿童向定位不符，全部替换**。引擎不用改，只换数据文件。

## 八、技术设计

沿用现有的**零依赖、零构建**架构（双击 `index.html` 就能玩，推 GitHub Pages 就是网站）。引擎需要加六块：

| 新增文件 | 作用 |
|---|---|
| `data/races.js` | 种族表 |
| `data/quests.js` | 任务表（危险等级、情报线索、敌人） |
| `data/enemies.js` | 敌人表（血量、弱点） |
| `src/math.js` | 题目生成器（三档 + 自适应） |
| `src/battle.js` | 战斗流程 |
| `src/memory.js` | 重生记忆管理 |

### 现有的「标记」字段直接升级成记忆层

第一版引擎里我已经留了 `标记` 和 `需要.标记` 两个接口，当时是给「怎么进的塔」这种小事用的。**重生机制正好架在这上面**：

```js
// 场景选项可以这样写
{ 文本: "再进一次那个谷仓",
  前往: "谷仓深处",
  需要: { 无标记: ["谷仓团灭"] } }   // 死过就不让直接莽进去

{ 文本: "带上一支火把（我记得怕火）",
  前往: "谷仓深处·有准备",
  需要: { 标记: ["谷仓团灭"] } }     // 死过之后才出现这条路
```

**第一版的设计接口直接派上用场，不用重构。**

### 存档结构扩展

## 九、分阶段计划

| 阶段 | 内容 | 产出 | 工作量 |
|---|---|---|---|
| **P1 引擎** | 数学题系统、种族、战斗、记忆层 | 能跑通一个完整任务的骨架 | 中 |
| **P2 内容** | 小镇 + 6 个任务 + 敌人表 + 题库 | 可玩约 1 小时 | **大（主体）** |
| **P3 打磨** | 音效、动画、家长设置、无障碍 | 可发布 | 中 |

**P1 必须先做完**（机制定了才知道内容要写什么）；**P2 是主体工作量**；P3 可以延后。

## 十、风险清单

| 风险 | 说明 | 对策 |
|---|---|---|
| **数学题变成作业感** | 孩子一旦觉得「在做题」就跑了 | 包装进叙事；答错不惩罚；每题不超过一屏三分之一 |
| **死亡机制伤害低龄玩家** | 8 岁孩子可能真的会难过 | 轮回数当徽章；重生必有确定收益；不嘲讽、不显示「Game Over」 |
| **文字量过大** | 8-10 岁读 100 字就累 | 每屏 ≤60 字；短句；关键词高亮 |
| **内容工作量被低估** | 6 个任务 × 15-20 场景 = 100+ 场景 | 先做 1 个任务当范本，模板化复制 |
| **难度自适应失灵** | 孩子可能卡在某一档反复失败 | 答错 2 次降档是硬规则，不靠猜 |

## 十一、下一步

方案确认后，建议的执行顺序：

1. 先做 **P1 引擎**（题目系统 + 战斗 + 记忆），用一个任务验证机制跑得通
2. 拿给目标年龄的孩子试玩那个任务，看两件事：**会不会读得太累**、**答错之后还愿不愿意继续**
3. 根据试玩结果再决定 P2 内容怎么写

**第 2 步不能跳。** 儿童游戏最大的风险是大人觉得设计得很合理、孩子根本不玩——这个只能靠真实试玩来发现。
