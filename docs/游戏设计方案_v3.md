## ★ 死亡政策（2026-10-08 立，取代 v1 第一条硬约束）

**v1 的第一条硬约束「任何失败都不能让孩子觉得我不会」已废止。** 理由：它与重生题材冲突——
不死的游戏里，「重生保留记忆」是句空话。实测：若把死亡率压到那条约束要求的水平（HP 20），
六座副本全程只有 **3%** 的玩家会死，最核心的机制变成死代码。

**取代它的是一条新约束，只有一句：**

> ### 死亡必须教会东西。
>
> 每一次死亡都要留下**确定、可复用、下次用得上**的情报。

死亡从「不能发生」变成「发生但必须有所得」。这条约束管四件事：

|#|要求|说明|
|-|-|-|
|1|**死因必须可理解**|孩子要能说出「我是被那个东西打死的」，不是「莫名其妙就没了」|
|2|**死因必须可复现**|同一处、同一动作，下次还会死。**死亡是知识，不是随机**|
|3|**必须留下具体情报**|敌人弱点、陷阱位置、正确解法、题目提示（见第二节 A6/A8）|
|4|**重生后必须能立刻用上**|情报要在下一次尝试里发挥作用，不能只是躺在日志里|

### 死亡率的定位：难度旋钮，不是禁区

**初始 HP 尚未定值。** 下表用不同 HP 做模拟，是为了让你看到「HP 取多少 → 死亡率多高」，
**不是已经选定 12**。

> 说明：HP = 体力属性初始值（1:1）。

|HP|单座死亡率|（参考）六座累计|（参考）六座全存活|**每座触发重生概率**|
|-|-|-|-|-|
|8|68.7%|4.12 次|0%|100%|
|**10（Lv1）**|**52.2%**|**3.13 次**|**1%**|**99%**|
|12|37.7%|2.26 次|6%|94%|
|14|25.7%|1.54 次|17%|83%|
|16|17.2%|1.03 次|32%|68%|
|20|7.0%|0.42 次|65%|35%|

> **口径**：攻击力 5（Lv1）、运气 1（Lv1）、准确率 60%、小怪免伤、营地回 6、
> 含剧情选错（2 处）与宝物购买（2 处）扣血。

**怎么读这张表**：

1. **HP 越低，死亡越常见**——8 是 68.7%，20 是 7.0%。HP 就是难度旋钮
2. **HP = 体力属性**（1:1），所以这张表实际是**等级成长表**：Lv1 是 HP 10（52.2%），
   每级 5 点全加体力，Lv5 就到 HP 30（见 1.1 实测）
3. **决策影响结果**：只管战斗是 34.3%，加上剧情选错和宝物购买是 52.0%——
   **34% 的死亡来自决策而非数学能力**（见 1.7）

> ⚠ **这条是本次改动最需要试玩验证的地方**：8-10 岁孩子真实的挫败容忍度，
> 以及「死了之后会不会看情报、还是直接烦躁退出」。大人算不出这个数。

### 与第二条硬约束的关系（保留并精化）

v1 第二条「不能有看起来像陷阱的选项」**保留**，但 D&D 式扣血让边界需要明确：

|允许|不允许|
|-|-|
|「打开铁箱（**-3 血**）」|「打开铁箱」→ 选完才告诉你扣了 3 血|
|「走上岔路」→ 遭遇战，扣血|「走上岔路」→ 无任何暗示却直接致死|
|高代价、高风险的选择|暗雷式惩罚|

**可以代价高昂，不可以是暗雷。** 孩子事后要能说「我知道会有危险，我赌了」，
而不是「我被骗了」。

## 一、属性系统

### 1.1 四维属性

|属性|作用|换算|
|-|-|-|
|**力量**|物理攻击力|1:1（1 点 = 1 点伤害）|
|**智力**|魔法攻击力|1:1|
|**体力**|生命上限|1:1（1 点 = 1 HP）|
|**运气**|答错后重试概率|1-100，见 1.2|

**Lv1 初始值**：力量 5 / 智力 5 / **体力 10** / 运气 1

体力 = HP（1:1），所以 Lv1 是 **10 HP**。**开局偏硬**，实测（每级 5 点全加体力）：

| 等级 | 体力 | 运气 | 单座死亡率（60% 准确率）|
|---|---|---|---|
| **1** | **10** | **1** | **52.1%** |
| 2 | 15 | 1 | 21.8% |
| 3 | 20 | 1 | 7.1% |
| 4 | 25 | 1 | 1.9% |
| 5 | 30 | 1 | 0.5% |

**Lv1 连打 6 座全存活概率只有 1.2%。** 开局基本必死，靠升级把体力拉起来才能求生。
这与重生题材相符，但难度是否偏硬需确认（见 B5）。

**为什么力量和智力都要**：它们不是两个数值，是**两种攻击方式**。每个敌人有物理弱点或魔法弱点（由线索揭示），选对了伤害翻倍。这样：

* 力量流和智力流都成立，不是「哪个数字大用哪个」
* **v2 里悬空的「弱点翻倍」终于有了落点**——弱点不是抽象属性，就是「该用剑还是该念咒」
* 题还是那道题，但**打之前要多想一步**（这怪怕什么？线索里说过吗？）

### 1.2 运气曲线（1-100）

答错之后，有概率**不扣血、直接重试一次**（运气值越高概率越大）。

**曲线约束**：r(20) = 20%，r(100) = 40%，20 点之后每点边际收益递减。
唯一满足这三个约束的对数形式：

```
L ≤ 20：  r(L) = L（1:1 线性，每点1个百分点）
L > 20：  r(L) = 20 + 20 × ln(L/20) / ln(5)
```

|运气|触发率|每点边际||运气|触发率|每点边际|
|-|-|-|-|-|-|-|
|1|1.0%|1.00/点||30|25.0%|0.41/点|
|10|10.0%|1.00/点||40|28.6%|0.31/点|
|15|15.0%|1.00/点||50|31.4%|0.25/点|
|**20**|**20.0%**|**0.62/点**||70|35.6%|0.18/点|
|25|22.8%|0.50/点||**100**|**40.0%**|**0.12/点**|

**三个关键结论**：

1. **加点甜区在 20 点以下**：1:1 换算，每点实打实 1 个百分点。
2. **20 点是边际骤降的拐点**：20→100 点，投 80 点只换 20 个百分点，边际降到 1/5。
3. **在 6 座副本制内，运气曲线的后半段到不了**：

   * **初始运气只有 1**，每级 5 点自由分配（升级制，见 1.4）
   * 6 座副本后约等级 5，累计 20 点 → 若全加运气则 **21 点（20.6%）**
   * 到 40 点（28.6%）需约 12 座；到 50 点（31.4%）需约 19 座
   * **40% 的上限是长线目标**，6 座制下实际天花板约 21%

> **A2 的弱点倒计时与运气曲线的关系**：运气触发「答错免伤」，倒计时触发「弱点双倍伤害」。
> 两者独立，互不干扰。运气是容错保护，倒计时是操作奖励。
>
> ⚠ **倒计时的总时长需要定标**，它直接决定弱点触发率（模拟：总时长取该档中位耗时的 2 倍时，
> 弱点率约 50-70%；取 1.5 倍时约 28%）。**触发率过高会让「×2 伤害」从奖励变成默认收益**，
> 该乘数就不再是操作奖励的体现。具体数值见第四节 B7。

### 1.3 伤害与生命

**答对一题 = 造成一次伤害**：

```
伤害 = 攻击力（力量或智力，1:1）
命中弱点（该用魔法却用了剑，反之亦然）→ 伤害 × 2
```

|敌人|HP|攻击力 5 时|命中弱点（×2）时|
|-|-|-|-|
|小怪 ×4|4|1 题|1 题|
|精英 ×1|12|3 题|2 题|
|BOSS ×1|24|**5 题**|3 题|

**单座副本总题量：12 题**（4 + 3 + 5）。平均实际作答 **16.6 题**（含答错重试）。

**答错扣血**：小怪免伤（0 伤），精英 / BOSS -2。营地回 6。另有 D&D 式扣血：剧情选错 -2、购买宝物 -3（见 1.6）。

> HP 上限 = 体力属性值（Lv1 为 10）。扣血数值 -2/-3 是配平起点，需试玩校准。

> ⚠ 这套数值是**配平起点，不是结论**。12 题（实际约 16.6 题）、Lv1 仅 10 HP 的容错，
> 都必须靠试玩调——8 岁孩子能承受的题量和挫败感只能实测。

### 1.4 属性点从哪来

**升级制**：杀死敌人和完成任务获得经验，**等级 × 100 = 升到下一级所需经验**，每级奖励 5 点自由分配。

| 来源 | 经验 |
|---|---|
| 小怪 | 5 |
| 精英怪 | 20 |
| 关底 BOSS | 100 |
| D 级任务完成 | 20 |
| C 级任务完成 | 50 |
| B 级任务完成 | 100 |
| A 级任务完成 | 400 |

**升级速度参考**（C 档任务：战斗 140 + 任务 50 = **190 经验/座**）：

| 完成副本数 | 累计经验 | 等级 | 累计属性点 | 距下级 |
|---|---|---|---|---|
| 0 | 0 | 1 | 0 | 100 |
| 1 | 190 | 2 | 5 | 110 |
| 2 | 380 | 3 | 10 | 220 |
| 3 | 570 | 3 | 10 | 30 |
| 4 | 760 | 4 | 15 | 240 |
| 5 | 950 | 4 | 15 | 50 |
| 6 | 1140 | 5 | 20 | 360 |

「距下级」= 还差多少经验升级。第 3 座和第 5 座是「空档期」（打完整座也不升级）。

**重生不清零属性**——孩子已得到的成长保留，只有记忆（情报）在新的轮次里更有用。

> ⚠ **一个后果需要你决定**：属性永久保留且可持续累积 → 等级越高，体力越多，死亡率越低。
> 同一座副本在第 1 级和第 5 级打，难度完全不同。这要怎么处理由你定（见 B2）。

### 1.6 配平实测（Lv1 基线：体力10 / 运气1 / 准确率 60%）

三类扣血来源：**战斗答错、剧情选错（2 处 × -2HP）、宝物购买（2 处 × -3HP）**。
小怪波免伤（0/2/2），营地回 6，攻击力 5。

**线索数 → 死亡率**（Lv1，HP 10）：

|线索|死亡率|平均实际题数|说明|
|-|-|-|-|
|0 条（硬打）|**52.1%**|16.6|BOSS 满血 24|
|1 条（弱点 ×2）|26.4%|13.9|攻击力翻倍|
|2 条（+BOSS 少 8 血）|17.9%|12.7|BOSS 16 HP|
|3 条（非战斗解法）|8.3%|9.8|跳过 BOSS 战|

**等级成长 → 死亡率**（每级 5 点全加体力，见 1.1）：

|等级|体力 = HP|单座死亡率|
|-|-|-|
|**1**|**10**|**52.1%**|
|2|15|21.7%|
|3|20|7.0%|
|4|25|2.0%|
|5|30|0.5%|

**准确率敏感性**（HP 10）：

|准确率|死亡率|
|-|-|
|50%|76.3%|
|60%|52.1%|
|70%|26.7%|
|80%|8.6%|

> **两个要紧的结论**：
> 1. **Lv1（10 HP）单座 52.1%**，连打 6 座全存活仅 1%——开局基本必死，靠升级求生
> 2. **死亡率对准确率极其敏感**（50% → 76%，80% → 8.6%）。而难度自适应把答对率
>    稳在 60-80%，所以**实际死亡率会落在 8%~52% 这个很宽的区间**里

### 1.7 死亡归因（这条决定死亡是否「教会东西」）

|等级|HP|只管战斗|含抉择+宝物|**决策占比**|
|-|-|-|-|-|
|**1**|**10**|**34.3%**|**52.0%**|**34%**|
|2|15|—|21.7%|—|

**Lv1 时，34% 的死亡由决策造成**（剧情选错、买宝物），其余 66% 来自战斗答错。
这符合 ★ 节的「死亡必须教会东西」：死亡要落在孩子**能改变的选择**上
（读不读线索、买不买宝物、走哪条路），而不是「你数学不好所以死了」。

### 1.8 线索价值（模拟参照，营6，小怪免伤，准确率60%）

|线索|死亡率|对比 0 线索|
|-|-|-|
|0 条（硬打）|52.1%|—|
|**1 条（弱点 ×2）**|**26.4%**|**降 2.0 倍**|
|2 条（BOSS 少 8 血）|17.9%|降 2.9 倍|
|3 条（非战斗解法）|8.3%|降 6.3 倍|

**线索价值远超任何宝物。** 3 条线索把死亡率从 52.1% 压到 8.3%（降 6.3 倍），
让「读线索比莽进去打」成为**被数字支撑的最优策略**——死亡政策放宽后，
这条设计意图更强了，因为**莽打的代价变得真实**。

### 1.9 宝物性价比（1 线索，模拟参照，准确率60%）

**攻击类宝物价值低，甚至有害**——原因：

* 小怪每只 4 HP，攻击 5 时**一击必杀**，加攻击对小怪波完全无效
* 精英 12 HP（攻5→3题、攻6→2题），BOSS 24 HP（攻5→5题、攻6→4题）：
  加 1 点攻击总共只省 2 题，而买它要花 3 血

**换算**：Lv1 只有 10 HP，**3 血 = 30% 的血量上限**。用 30% 血量换少答 2 题，
在 60% 准确率下**期望只值 1.2 血**（每题答错概率 40%，扣 2 血）。

**结论**：副本内宝物应以**防御/工具**为主（如护符：每战首次答错免伤），
攻击加成改为**跨副本持久装备**（摊到多座副本后才划算）。

> 具体数值待定：护符的准确收益需要单独模拟，且与「每战首次」的定义有关
> （一局有 3 场战斗，最多免 3 次）。见 B12。

### 1.10 五个种族（本轮开放）

| 种族 | 能力 | 机制 | 频次 |
|---|---|---|---|
| **狗** | 嗅觉 | **10% 概率额外获取一件装备** | 每天 1 次 |
| **熊** | 厚皮 | **受到的伤害 -2 点** | 常驻 |
| **猫** | 智力 +5 | 智力 5 → 10（魔法攻击力翻倍） | 常驻 |
| **鳄鱼** | 死亡翻滚 | 面对敌人题目时，可直接造成**力量 × 3 = 15** 伤害 | 每天 1 次 |
| **鹦鹉** | 灵敏反应 | **答题时间额外 +5 秒** | 常驻 |

> **一场地下城 = 12 小时**（见 2.5）。一天 24 小时 → 每天可打 2 座。
> 因此「每天一次」的能力 = **每 2 座可用 1 次**，6 座全程共 3 次。

#### 实测强度差异（Lv1，60% 准确率，单座死亡率）

| 种族 | 死亡率 | 相对基线 | 实际收益 |
|---|---|---|---|
| 基线（无能力） | 52.1% | — | — |
| **熊** | **0.0%** | **免疫全部伤害** | 见 B8 |
| 猫 | 26.3% | -25.8pt | 总题数 12 → 9 |
| 鳄鱼 | 26.2% | -25.9pt | 一次打掉 BOSS 的 62% 血量 |
| 鹦鹉 | ~52% | 死亡率不变 | 弱点触发率 +8~25pt（见下）|
| 狗 | 52.1% | **无战斗收益** | 6 座全程期望 0.3 件装备（见 B9）|

#### 各能力的作用维度不同

五族**不是同一维度的差异**，需分开评估：

| 种族 | 维度 | 生效方式 |
|---|---|---|
| 熊 | 生存 | 每次受伤 |
| 猫 | 输出 | 每次攻击（题数减少 25%）|
| 鳄鱼 | 爆发 | 一次（每天）|
| 鹦鹉 | 时间 | 每次答题（影响弱点判定）|
| 狗 | 掉落 | 概率触发（每天一次判定）|

**鹦鹉的收益随题目难度递减**（+5 秒是固定值）：

| 档位 | 总时长 | 鹦鹉后 | 弱点率变化 |
|---|---|---|---|
| 低档 47+38 | 13s | 18s | 28% → **53%**（+25pt）|
| 中档 234×3 | 23s | 28s | 28% → 43%（+15pt）|
| 高档 234×27 | 42s | 47s | 28% → 36%（+8pt）|

（假定总时长 = 该档中位耗时 ×1.5，弱点窗口 = 总时长一半）

方向上与猫**相反**：档位越高（越熟练），鹦鹉收益越小；而猫的智力 +5 在
敌人 HP 固定时，高档位收益更大。

## 二、死亡与重生（修订）

### 2.1 提示机制（本版新增，也是你最看重的一条）

**触发条件**：某个选项的数学题**导致你死亡**。系统记下 `{副本, 场景, 题目}`。

> **⚠ 这里有个必须先定的机制缺口。** v3 沿用「答错只扣血、血量耗尽才死」，
> 那么死亡**通常不是某一道题造成的，而是一连串答错累积的结果**——
> 最后一题只是压死骆驼的那根稻草。于是「对应造成死亡的选项」到底指哪一道？
>
> 三种归因方式，效果差别很大：
>
> | 方式 | 给提示的题 | 问题 |
> |---|---|---|
> | **a 致命一击那题** | 只有最后一道 | 那题可能只是运气不好，**不是孩子真正的弱项** |
> | **b 本次死亡中答错的所有题** | 全部答错的 | 提示最多，但可能一次给 3-4 道，信息过载 |
> | **c 死亡场景里的题** | 只有当场那几道 | 介于两者之间 |
>
> **我建议 b**：孩子真正的弱项就是那几道答错的题，而且这正好接上 v2 的
> 「答错过的题重生后再出现一次」——**它们本来就是同一批题**。
> 若担心一次给太多，可以只给**错得最多的那两类题型**。

**重生后再回到同一题** → 题目下方出现提示。

**提示是「方法」不是「答案」**：

> 石门上浮出符文：
>
> **47 + 38 = ?**
>
> 💡 你记得上次是怎么卡住的：
> 先算十位 40+30=70，再算个位 7+8=15，最后 70+15。
>
> `[ 60 ]  [ 75 ]  [ 85 ]  [ 95 ]`

孩子看完这一步，基本就能自己算出来了——**这正是你要的效果**，也是「提示」和「给答案」的分界线。

### 2.2 提示会升级

死第二次，提示更细：

|死法|提示详细度|
|-|-|
|第一次死在这题|给出**分步方法**（如上例）|
|第二次死在同一题|提示**算出第一步**：「40+30 你已经会了，是 70。剩下 7+8。」|
|第三次|保留第二步，把最后一步留给孩子|

**永远不给最终答案。** 最后一步必须孩子自己算——那是他唯一要学的东西。

### 2.2b 提示绑「这道题」还是「这个题型」（A8）

这是提示机制**成败的关键**，也是最容易做错的一处。

孩子死在那道题上，是 `47 + 38`。重生后回到**同一道题**，提示当然管用。
但真正的考验是：下一道**同类的新题** `56 + 27` 出现时，提示还在不在？

|做法|结果|
|-|-|
|只绑 `47+38` 这一道|孩子**只会这一道**，换个数字又卡住 → **没有学习迁移**，提示沦为过关工具|
|**绑题型「两位数进位加法」**|孩子学会的是方法，换数字也会 → **这才是真正的学习**|

**我建议绑题型，但提示内容用具体题目演示：**

> 第一次死在这类题 → 完整分步演示（用 `47+38` 讲）
> 下次遇到同类新题 `56+27` → 提示缩短，只提醒关键一步：
> 💡 你学过这种题：先算十位，再算个位，最后加起来。

**这样才把「错题复习」和「提示」接成一件事**——v2 里那条「答错过的题重生后会再出现一次」
本来就是同类的重现，现在有了提示，它就从「再考你一次」变成「再教你一次」。

> ⚠ 代价要说清：绑题型意味着**要维护「题型」这个概念**（如「两位数进位加法」「表内乘法」），
> 题库得给每道题打题型标签。这会让 `src/math.js` 稍微复杂一点，但换来的是真正的学习迁移。

### 2.3 这条机制为什么是对的

**主题上**：重生题材的核心是「我记得上次为什么死了」。而**这道题的提示，就是那段记忆本身**。
机制和叙事在这里是同一件事——不是一个系统加一个皮肤。

**教学上**：这是标准的**脚手架（scaffolding）**——孩子卡住时给支撑，会了就撤掉。
比「再出十道同类题」有效得多，而且孩子不会觉得自己在被罚。

**情绪上**：死亡从「我输了」变成「**我知道了**」。孩子会主动想去看看那道题现在给什么提示。

### 2.4 重生清空什么（沿用 v2）

|清空|保留|
|-|-|
| 装备、银币 | **全部记忆**：四维属性、死过副本的记录、题目提示 |

> **属性不清零**（2026-10-08 定）。死亡只丢装备和银币，等级、属性点、经验全部保留。

### 2.5 一趟冒险的完整循环

**六座地下城不是一口气打完的。** 一趟只打一座，然后回城。

**时间单位：一场地下城 = 12 小时。** 一天 24 小时 → **每天可打 2 座**。
「每天一次」的种族能力因此 = 每 2 座可用 1 次。

```
小镇（接任务）
   ↓
地下城（小怪 → 精英 → 营地 → BOSS）
   ↓
回城 · 交任务（拿报酬和经验）
   ↓
休息（住酒店 → 回满血、存进度）
   ↓
看悬赏板，接下一个任务 ←──┐
   ↑                       │
   └───────────────────────┘
```

**为什么这样设计**：

| 好处 | 说明 |
|---|---|
| **单次时长可控** | 一座 10-15 分钟，适合 8-10 岁孩子的注意力 |
| **每座独立结算** | 难度只需按**单座**配平，不用考虑「连打六座」的累积压力 |
| **死亡不等于白玩** | 死在地下城里，回城后进度仍在，只是这次任务没完成 |
| **有自然的休息点** | 住酒店是明确的「今天到此为止」信号，家长也好管理 |

**住酒店的作用**：回满血 + 存档。相当于 v2 里营地补给的「城外版」。

**时间系统的待定项**（见 B10）：住酒店是否消耗小时、战斗/解谜是否单独计时、
死亡重生时时间是否回退、「每天」的重置点是午夜还是睡醒。

### 2.6 速通通道（沿用 v2）

死过的副本，重生后多一个选项：

```
> 你已经死在这里一次了。
> 要走老路吗？会快得多，但路上没有补给。

  [ 走老路，直奔深处 ]    ← 3-5 分钟
  [ 按原路再走一遍 ]      ← 10-15 分钟，可重新拿线索
```

## 六、存档与账号系统

> 本节讨论「在网站上自动存档 / 登录账号」功能的可行性与分层方案。

### 核心约束：GitHub Pages 是纯静态托管

游戏发布在 GitHub Pages（`https://ypingzhao.github.io/Oscar-adventure-game/`），这是纯静态文件服务：

- 没有服务器进程，没有数据库，没有后端 API
- 所有写操作只能在浏览器本地完成，**无法在服务端持久化跨设备的用户数据**
- 「注册账号 → 登录 → 云端存档」这件事，GitHub Pages 本身做不到

这不是暂时的工程限制，是静态托管的物理边界。

### 分层方案

| 层 | 方案 | 跨设备 | 需要登录 | 复杂度 | 推荐度 |
|----|------|--------|----------|--------|--------|

### L0：自动存档（当前已有，需补强）

localStorage 键 `oscar-adventure-save-v1` 已在代码中存在。需要补充两件事：

**自动存档触发点**（任意一条满足即写盘）：

- 离开场景时
- 属性或 HP 发生变化时
- 进入 / 离开地下城时
- 交任务时
- 死亡并重生后

**防崩坏双槽写入**：

```
oscar-save-slot-a    ← 存档数据
oscar-save-slot-b    ← 存档数据（备份）
oscar-save-pointer   ← "a" 或 "b"（上一次成功写入的槽名）
```

写入顺序：先写**非当前槽** → JSON 解析验证通过 → 翻转指针 → 再覆盖旧槽。  
读取时：读指针 → 读对应槽 → 解析失败则 fallback 到另一槽。  
这样即使写到一半断电，也能从另一槽完整恢复。

**存档结构（草案）**：

```json
{
  "version": 1,
  "savedAt": "2026-10-08T12:00:00Z",
  "character": {
    "name": "Oscar",
    "race": "cat",
    "level": 2,
    "exp": 145,
    "stats": { "str": 5, "int": 10, "hp": 15, "maxHp": 15, "luck": 3 },
    "inventory": [],
    "gold": 20
  },
  "world": {
    "currentScene": "town_inn",
    "completedDungeons": ["dungeon_farm"],
    "activeQuest": null,
    "gameTime": 14
  },
  "deathLog": [
    {
      "dungeonId": "dungeon_farm",
      "causeTypes": ["2digit_addition"],
      "runAt": "2026-10-08T10:00:00Z"
    }
  ]
}
```

`deathLog` 字段承接死亡政策（★节）：重生后展示「上次死亡时遇到了哪类题」，让孩子立刻用上情报。

### L1：多存档槽位

起始界面提供 **3 个存档槽**，支持不同孩子共用一台设备、或同一孩子用不同种族体验。  
每个槽位展示：角色名、种族图标、等级、最后保存时间。

删除保护：**不做弹窗确认**（8 岁孩子会点反），改为**长按 2 秒**才触发删除，松手则取消。

### L2：存档码（推荐作为跨设备方案）

把存档 JSON 经 `CompressionStream`（现代浏览器内置，无需引入库）压缩后 Base64 编码，  
生成一串约 300–500 字符的存档码。玩家复制存档码，在新设备粘贴即可恢复进度。

**存档码格式**：

```
[1字节版本前缀][4字节 CRC32 校验][Base64(deflate压缩的JSON)]
```

**优点**：

- 零后端，零登录，完全在浏览器端运行
- 对家长友好：不需要注册任何账号，也不需要联网
- 对 8–10 岁孩子足够直观：「这串字就是你的存档，发给爸爸保存一下」

**UI 位置**：

- 游戏内暂停菜单 → 「导出存档码」→ 点击即复制到剪贴板，同时显示「已复制！」提示
- 起始界面 → 「用存档码继续」→ 粘贴后自动解析并载入

### L3：GitHub Gist 云端同步（当前不推荐实现）

技术上完全可行，不违反静态托管限制：

1. 用 **GitHub OAuth Device Flow**（设备码授权）：浏览器直接向 GitHub 请求，无需暴露 client secret，无需后端
2. 获得 token 后，用 **GitHub REST API** 写入 / 读取用户私有 Gist，实现真正的跨设备云端存档
3. 整个流程在浏览器内完成，GitHub Pages 托管即可支持

**为什么当前不推荐实现**：

- 目标玩家 8–10 岁，**没有 GitHub 账号**；父母注册并代为登录增加了大量摩擦
- Device Flow 授权需要跳转 GitHub 网页、手动输入设备码、确认授权——对儿童极不友好
- 实现工作量约为 L0+L1+L2 的 3 倍，且额外依赖 GitHub API 可用性
- **L2（存档码）已经能解决跨设备问题**，成本低得多

**触发重新评估的条件**：

- 游戏扩展到 6 座副本以上，存档码超过 1KB 开始不适合手动传输
- 或者面向更大年龄段（12+，用户自己有 GitHub 账号）

### 结论

**V1 实现清单**（GitHub Pages 静态托管内可全部完成）：

| 优先级 | 任务 | 依赖 |
|--------|------|------|
| P0 | L0 双槽防崩坏写入 + `deathLog` 字段 | 无 |
| P1 | L1 三存档槽位起始界面 | P0 完成后 |
| P2 | L2 存档码导出 / 导入（`CompressionStream` + Base64） | P0 完成后 |
| 暂缓 | L3 GitHub Gist 云端同步 | 等内容量增加后再评估 |

**不在 V1 做**：账号注册、密码、服务端 API、数据库。  
若将来确实需要真正的账号体系，需将托管迁移到支持后端函数的平台（如 Vercel、Cloudflare Pages + Workers），届时可用 Cloudflare KV 存档，成本极低。
