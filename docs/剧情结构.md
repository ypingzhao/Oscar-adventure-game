# 剧情结构

改剧情前先看这张图。**凡是「前往」指向的 id，必须在本文件里能找到对应场景。**

```
雨夜小屋  ← 起点
│  拿手电筒 / 拿手电筒+铜钥匙 / 什么都不拿
│
└─▶ 岔路口
    │
    ├─▶ 塔前 ──┬─[需 铜钥匙]─▶ 塔顶 ──┬─[一次性]─┐
    │          │                      └──────────┴─▶ 塔顶·下望
    │          ├─▶ 塔后 ──[需 手电筒]─▶ 塔顶        └─▶ 结局：灯塔守望者
    │          └─▶ 退 岔路口
    │
    └─▶ 村子 ─▶ 结局：无人村
```

## 两个结局

| 结局 | 触发 | 说明 |
|---|---|---|
| 灯塔守望者 | 上塔顶，走到栏杆边 | 通行结局；摘不摘徽章都到这里 |
| 无人村 | 走右边去村子 | 不需要任何道具 |

## 留的接口（现在没用上，将来可以接）

- `标记` 字段：`塔前` 的「拿铜钥匙开锁」会记下 `从正门进塔`，
  `塔后` 会记下 `从裂缝进塔`。目前没有选项在读这两个标记——
  留着的用途是：将来想让「怎么进的塔」影响塔顶看到的文字，
  在 `塔顶` 的选项里加 `需要: { 标记: ["从正门进塔"] }` 就行。
- `无标记` 字段：用来让某条路在做过某件事之后失效，目前没用上。
- `物品.可携带`：现在不限制负重。将来真要做背包上限时字段已经在了。

## 自检

每次改完剧情跑：

```powershell
node tools/check_story.js
```

七项检查，全过才算改完——特别是第 4 项「有没有走不到的场景」
和第 7 项「空手能不能走到结局」，这两个靠肉眼看不出来。
