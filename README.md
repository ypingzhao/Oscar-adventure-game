# Oscar 冒险记

一个纯网页的文字冒险游戏。零依赖、零构建——双击 `index.html` 就能玩，
推上 GitHub Pages 就是一个可以直接发给别人玩的网站。

## 怎么跑起来

**最快**：双击 `index.html`。

**推荐**（避免个别浏览器对本地文件的限制）：

```powershell
cd "D:\0 AI 代码尝试\Bitto\web game design"
python -m http.server 8000
```

然后开 <http://localhost:8000>。

## 目录结构

```
index.html          页面骨架：顶栏 / 正文 / 选项 / 背包四个容器
src/main.js         游戏引擎：读状态→渲染→处理点击→存档
src/style.css       全部样式，主色在文件顶部 :root 里
data/scenes.js      ★ 剧情：所有场景与选项
data/items.js       ★ 物品表
assets/images/      图片（现在空着）
assets/audio/       音频（现在空着）
docs/剧情结构.md     故事走向图，改剧情前先看这个
```

带 ★ 的两个文件是**内容**，其余是**引擎**。改故事基本只动那两处。

## 怎么改剧情

### 加一个场景

在 `data/scenes.js` 的 `window.场景表` 里加一条：

```js
"塔底的储藏间": {
  标题: "塔底的储藏间",
  正文: [
    "第一段话。",
    "第二段话。"
  ],
  选项: [
    { 文本: "推门出去", 前往: "塔前" }
  ]
}
```

再在某个场景的「选项」里加一条指过去，就接上了：

```js
{ 文本: "钻进那扇半开的小门", 前往: "塔底的储藏间" }
```

### 选项能带的字段

| 字段 | 作用 |
|---|---|
| `文本` | 按钮上写的话（必填） |
| `前往` | 点完去哪；不填就是留在原地 |
| `获得` | `["手电筒"]` 拿到物品，名字必须在 `items.js` 里存在 |
| `标记` | `["从正门进塔"]` 记下一个事实，供后面判定 |
| `需要` | `{ 物品: [...], 标记: [...], 无标记: [...] }` 不满足则按钮变灰 |
| `一次性` | `true` = 选过之后不能重选 |

**条件不满足的选项不会被藏起来，只是变灰点不动。** 这是故意的——
让玩家知道「这儿确实还有别的路，只是我还没找到钥匙」，
比让路凭空消失体验好得多。

### 做一个结局

**不给这个场景写「选项」字段**，它就是结局。引擎会自动补上结局名和重开按钮。

### 加一件物品

在 `data/items.js` 的 `window.物品表` 里加一条，键名就是游戏里显示的名字。
`描述` 会变成背包里悬停提示。

## 存档

进度存在浏览器 `localStorage` 里，键名 `oscar-adventure-save-v1`。
顶栏「重新开始」按钮会清掉它。

**换内容时注意**：如果改了 `scenes.js` 里某个 `id`，老存档会指向不存在的场景——
引擎检测到会自动从头开始，不会白屏。

## 改剧情后一定要跑的自检

剧情图最容易出的暗坑是「选项指向一个不存在的场景」，
这种错在页面上表现为点了没反应，不报错，很难查。放一个自检脚本在仓库里：

```powershell
node tools/check_story.js
```

它会查七项：起始场景是否存在、所有「前往」目标是否存在、
所有「获得」物品是否存在、有没有走不到的场景、结局有几个、
有没有死路、以及**空手能不能走到结局**（防止不带道具就卡死）。

## 发布成网站

仓库推上 GitHub 之后：

1. 打开 <https://github.com/ypingzhao/Oscar-adventure-game/settings/pages>
2. **Source** 选 `Deploy from a branch`
3. **Branch** 选 `main`，目录选 `/ (root)`，保存
4. 等一两分钟，访问 <https://ypingzhao.github.io/Oscar-adventure-game/>

之后每次 `git push`，网站会自动更新。

> 页面用的是普通 `<script>` 而不是 ES module，数据挂在 `window` 上——
> 就是为了让「本地双击打开」和「线上访问」两种跑法行为完全一致。
> 如果以后改成 `import`，`file://` 会被浏览器的跨域策略挡住。
